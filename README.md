# Student Privacy Management System Using Hyperledger Fabric

## Project Overview

This project demonstrates a blockchain-based authorization system for protecting access to student information.

It integrates Hyperledger Fabric, Go smart contracts, and an SQLite database. The blockchain determines whether an organization is authorized to access a student record before the backend retrieves the corresponding information from the database.

## Technologies Used

- **Hyperledger Fabric:** Permissioned blockchain network
- **Go:** Smart contract and backend development
- **SQLite:** Local database for student information
- **Hyperledger Fabric Gateway SDK:** Communication between the backend and blockchain
- **Docker:** Hosting the Fabric network components

## System Architecture

The system consists of three main components:

1. **Blockchain network:** Hyperledger Fabric maintains student registration and organization ownership information.
2. **Smart contract:** Implements `RegisterStudent` and `CheckAccess` to register students and evaluate organization-based access permissions.
3. **Backend and database:** The Go application requests authorization from the blockchain and retrieves student information from SQLite only when authorization succeeds.

### Authorization Workflow

1. An organization requests access to a student record.
2. The backend connects to Hyperledger Fabric using that organization's identity.
3. The smart contract checks whether the organization is authorized.
4. If authorization succeeds, the backend retrieves the student record from SQLite.
5. If authorization fails, no student information is retrieved.

## Testing and Results

The application was tested using a two-organization Hyperledger Fabric network.

| Test Case | Expected Behavior | Observed Result |
|---|---|---|
| Org1 accesses STU001 | Access granted | ACCESS GRANTED |
| Org2 accesses STU001 | Access denied | ACCESS DENIED |
| Org1 accesses STU999 | Student not found | Chaincode returned student not found |

All three tests prevented unauthorized or nonexistent student records from being displayed.

## Running the Demonstration

### Prerequisites

- Go
- Docker Desktop
- Hyperledger Fabric samples and binaries
- A running Fabric test network with channel `mychannel`
- The `studentprivacy` chaincode deployed on the channel
- Organization administrator certificates and private keys generated by the Fabric test network

The backend currently expects the Fabric test network to be located at `~/fabric-projects/fabric-samples/test-network`.

From the `backend` directory, build the application:

```bash
go mod tidy
go build -o student-backend .
```

Run the authorized-access test:

```bash
./student-backend -org=1 -student=STU001
```

Run the unauthorized-access test:

```bash
./student-backend -org=2 -student=STU001
```

Run the unregistered-student test:

```bash
./student-backend -org=1 -student=STU999
```

The demonstration uses fictional student records.

## Security Considerations and Limitations

- The blockchain stores student identifiers and organization ownership information rather than full academic records.
- The SQLite database stores student details locally.
- Access control is based on organization membership, not individual student consent or role-based permissions.
- The demonstration uses Fabric administrator identities and is not a production authentication system.
- The local SQLite database is not independently protected against direct access.
- The implementation is intended for educational and research demonstration purposes, not production use with real student data.

## Future Improvements

Potential extensions include student-controlled consent, role-based permissions, stronger database security, improved error handling, and a web interface for managing access requests.

## Conclusion

This project demonstrates how a permissioned blockchain can serve as an authorization layer for a traditional database. Hyperledger Fabric evaluates organization-based permissions, while SQLite stores the actual student information, illustrating a hybrid approach to student data access management.
